## Installation

```cargo
cargo add audiocn
```

## Usage

```rust
use audiocn::LevelMeter;
```

```rust
LevelMeter::new("mic").aria_label("Microphone level").peak_db(-12.)
```

`LevelMeter::new` takes an element id, which keeps the meter's ballistics and peak hold between renders. Give each meter an id that is unique among its siblings.

With no children, `LevelMeter` renders one track per channel with a peak bar and a peak-hold tick. Add children to control the anatomy.

## Anatomy

```rust
use audiocn::{
    LevelMeter, LevelMeterBar, LevelMeterChannel, LevelMeterChannels, LevelMeterClip,
    LevelMeterHold, LevelMeterMeasure, LevelMeterScale, LevelMeterTrack, LevelMeterValue,
};

LevelMeter::new("program")
    .source(meter.clone())
    .child(
        LevelMeterChannels::new()
            .child(
                LevelMeterChannel::new().index(0).child(
                    LevelMeterTrack::new()
                        .child(LevelMeterBar::new().measure(LevelMeterMeasure::Rms))
                        .child(LevelMeterBar::new().measure(LevelMeterMeasure::Peak))
                        .child(LevelMeterHold::new()),
                ),
            )
            .child(LevelMeterScale::new()),
    )
    .child(LevelMeterValue::new())
    .child(LevelMeterClip::new())
```

## Feeding data

A meter accepts levels three ways. See [Feeding data](/docs/gpui/concepts/feeding-data).

```rust
use audiocn::{ChannelLevel, LevelMeter, LevelMeterActions, MeterFrame};

// A source: the meter reads it while painting and asks for frames only while it moves.
LevelMeter::new("a").source(meter.clone())

// Values: for slow data. Ballistics smooth the movement.
LevelMeter::new("b").peak_db(-9.1).rms_db(-18.)

// A handle: for callers that own their own frame loop.
let actions = LevelMeterActions::new();
LevelMeter::new("c").actions(actions.clone())
// later
actions.paint(MeterFrame::mono(ChannelLevel::new(-9.1)), cx);
```

A `FrameSource` is a shared slot, not an event stream: producers on any thread `emit` into a `FrameEmitter`, and a settled meter polls the source so new frames wake it.

## Theming

The meter paints with the active `audiocn::Theme`. The React CSS variables are theme fields and builder options here:

| React | GPUI |
| --- | --- |
| `--meter-ok`, `--meter-warn`, `--meter-clip` | `Theme::meter_ok`, `meter_warn`, `meter_clip`, or `LevelMeter::zone_color(zone, color)` for one meter |
| `--meter-thickness` | `.size(AudioSize)`: `Sm` 4px, `Default` 8px, `Lg` 12px |
| `--meter-gap` | 4px between channels; restyle `LevelMeterChannels` with `.gap(..)` |
| `--meter-level`, `--meter-rms`, `--meter-hold` | `use_level_meter(..).channel_reading()`: `level`, `rms`, `hold`, 0..1 |

The React data attributes are readings you can branch on:

| React | GPUI |
| --- | --- |
| `data-orientation`, `data-variant`, `data-size` | `LevelMeterContext::orientation`, `variant`, `size` |
| `data-zone` | `context.root.zone` for the root, `channel_reading().zone` for a channel |
| `data-clipping` | `context.root.clipping`, or `LevelMeterActions::clipping(cx)` |
| `data-active` | `channel_reading().active` |
| `data-dimmed` | `AudioConfig::dimmed`, which draws the meter at 50% |
| `data-measure` | `LevelMeterBar::measure(..)` |

`LevelMeterHold::color(..)` sets the peak-hold tick, which defaults to `foreground` at 80%.

## Accessibility

- The root has the AccessKit role `Meter` with its minimum, maximum and current value in dB, and a value text such as "−12.0 dB". These update at most four times a second.
- Give every meter a name with `.aria_label(..)`.
- With reduced motion, the meter shows the current level four times a second instead of animating. GPUI has no system query for it, so set it with `audiocn::signal::reduced_motion::set_reduced_motion(true, cx)`.

### LevelMeterScale, LevelMeterValue, LevelMeterClip

These wrap [`DbScale`](/docs/gpui/components/db-scale), [`DbReadout`](/docs/gpui/components/db-readout) and [`ClipIndicator`](/docs/gpui/components/clip-indicator), and take their builder options. The range, orientation and data come from the meter. `LevelMeterValue` and `LevelMeterClip` also take `.id(..)` when a meter has more than one.
