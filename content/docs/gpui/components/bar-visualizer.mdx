## Installation

```cargo
cargo add audiocn
```

## Usage

```rust
use audiocn::BarVisualizer;
```

```rust
BarVisualizer::new("voice")
    .aria_label("Voice activity")
    .source(visual.clone())
    .text_color(cx.theme().primary)
```

`BarVisualizer::new` takes an element id, which keeps the bar levels between renders. Bars take their color from the text color, so set it with `.text_color(..)`. Bars paint in one canvas on the animation frame.

### Idle and loading

`.idle(..)` decides what bars do without a signal: `BarIdle::Static`, `Pulse` or `Wave`, from `audiocn::audio::bar_levels`. `.loading(true)` runs a sweep, for connecting or thinking states.

## Theming

The React CSS variables are builder options here:

| React | GPUI |
| --- | --- |
| `text-*` class | `.text_color(color)` |
| `--bar-width` | `.bar_width(Pixels)`, maximum bar width, default 6px |
| `--bar-gap` | `.bar_gap(Pixels)`, gap between bars, default 3px |
| `--bar-radius` | `.bar_radius(Pixels)`, bar corner radius, default fully rounded |
| `data-active` | `BarVisualizerActions::is_active(cx)`: the signal is above the floor |

The bars are painted, not elements, so `data-loading` and `data-index` have no equivalent.

## Accessibility

The root has the AccessKit role `Image` and the label "Audio visualizer". Pass `.aria_label(..)` to describe what it shows, or `.aria_hidden(true)` when it is decorative next to a labelled meter.
