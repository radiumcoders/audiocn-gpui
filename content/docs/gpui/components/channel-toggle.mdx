## Installation

```bash
cargo add audiocn
```

## Usage

```rust
use audiocn::{MonitorToggle, MuteToggle, SoloToggle};
```

```rust
let view = cx.entity();

MuteToggle::new("mute")
    .pressed(self.muted)
    .on_pressed_change(move |muted, _, cx| {
        view.update(cx, |this, cx| {
            this.muted = muted;
            cx.notify();
        })
    })
    .child("M")
```

```rust
SoloToggle::new("solo").child("S")
```

The presets set the tone and a default `aria_label`. Children are a letter, a word or an icon; nothing is rendered by default. `.icon(IconName::Headphones)` (from `audiocn::ui::icons`) adds an icon at the toggle's 14px size. Use `ChannelToggle` with a `.tone(..)` for anything else.

`MuteToggle::new`, `SoloToggle::new` and `MonitorToggle::new` return a `ChannelToggle`, so every builder method below works on them. The id keeps focus and uncontrolled state between renders. Leave out `.pressed(..)` for an uncontrolled toggle.

## Theming

The toggle paints with the active `audiocn::Theme`. The React tokens and attributes map to theme fields and builder options:

| React | GPUI |
| --- | --- |
| `--channel-mute`, `--channel-solo`, `--channel-monitor` | `Theme::channel_mute`, `channel_solo`, `channel_monitor`, with their `*_foreground` fields for the text |
| `data-pressed` | `.pressed(..)` or `.default_pressed(..)` |
| `data-tone` | `.tone(ChannelToggleTone::Mute)`, `Solo`, `Monitor` or `Neutral` |

Set the colours for the whole app with `audiocn::theme::set_theme(theme, cx)`. `channel_toggle_variants(theme, size, tone, variant, pressed)` returns the resolved `ChannelToggleStyle`, if you draw a matching button yourself.

## Accessibility

Toggles are focusable, and Space or Enter toggles them. They are exposed through GPUI's AccessKit tree as buttons with a toggled state. The presets are labelled "Mute", "Solo" and "Monitor"; override `.aria_label(..)` to name the channel, such as "Mute microphone".
