<details>
<summary>About the demo signal helper</summary>

The example uses `use_demo_mixer` from `audiocn::signal::demo_signal`. Unlike React's docs-only `useDemoMixer`, it ships in the crate, so there is nothing to copy. It builds on [`use_demo_signal`](/docs/gpui/hooks/use-demo-signal) and follows the state of [`use_mixer`](/docs/gpui/hooks/use-mixer).

Mono channels feed both sides. The helper estimates peak by summing amplitudes and RMS by summing powers. For audio samples, connect [`WebAudioMixer`](/docs/gpui/hooks/use-web-audio-mixer) to the same components.

```rust
use audiocn::signal::demo_signal::{DemoMixerChannel, DemoSignalOptions, use_demo_mixer};

let state = mixer.read(cx).state.clone();
let demo = use_demo_mixer("demo", &channels, &state, window, cx);

demo.source("mic"); // one channel's meter source
demo.master; // the stereo master
```

</details>

## Installation

```bash
cargo add audiocn
```

## Usage

```rust
use audiocn::{
    ChannelStrip, ChannelStripVariant, Mixer, MixerChannels, MixerHeader, MixerMaster,
    MixerSeparator, MixerTitle, Orientation,
};
```

```rust
Mixer::new("mixer")
    .orientation(Orientation::Vertical)
    .child(MixerHeader::new().child(MixerTitle::new("Audio mixer")))
    .child(MixerChannels::new().children(
        channels.iter().map(|channel| ChannelStrip::new(channel.id.clone())),
    ))
    .child(MixerSeparator::new())
    .child(MixerMaster::new().child(
        ChannelStrip::new("master").variant(ChannelStripVariant::Master),
    ))
```

The mixer holds no audio and no state. Pair it with [`use_mixer`](/docs/gpui/hooks/use-mixer) for state and [`WebAudioMixer`](/docs/gpui/hooks/use-web-audio-mixer) for sound, or with your own engine.

The mixer passes its settings down as an `AudioConfig` instead of React context, the same way a [channel strip](/docs/gpui/components/channel-strip#how-it-passes-settings-down) does. Strips inside a mixer pick it up on their own, merge their own settings over it, and hand the result to the meters, faders and toggles given through `.meter(..)`, `.fader(..)`, `.controls(..)` or `.child_with(..)`. For anything else you build inside the mixer, read the config with `Mixer::child_config()`, or add the child with `Mixer::child_with(|mixer, window, cx| ..)` and use `mixer.config`.

## Anatomy

```rust
Mixer::new("mixer")
    .child(
        MixerHeader::new()
            .child(MixerTitle::new("Audio mixer"))
            .child(MixerActions::new()),
    )
    .child(MixerChannels::new())
    .child(MixerEmpty::new())
    .child(MixerSeparator::new())
    .child(MixerMaster::new())
```

## Behaviour

- Every meter in the mixer shares `min_db`, `max_db`, `zones` and `ballistics`, so levels compare fairly across channels. The meter gets them through its strip's config, so add meters with `ChannelStrip::meter` or `child_with`.
- With focus on a control in a strip, Ctrl + arrow keys (Cmd + arrow keys on macOS) move to the same control on the neighbouring strip: left and right in a console, up and down in rows. Tab still moves through every control in order.
- `MixerChannels` scrolls along the strip axis when strips overflow; the master area stays in place.
- `MixerEmpty` appears when `MixerChannels` has no children.
