## Installation

```bash
cargo add audiocn
```

## Usage

```rust
use audiocn::Fader;
```

```rust
let view = cx.entity();

Fader::new("microphone")
    .aria_label("Microphone")
    .value(self.gain_db)
    .on_value_change(move |db, _window, cx| {
        view.update(cx, |this, cx| {
            this.gain_db = db;
            cx.notify();
        });
    })
```

The value is always in dB. The taper decides where each dB value sits on the travel. The thumb snaps to 0 dB while dragging, and double-clicking it resets.

`Fader::new` takes an element id, which keeps the drag, focus and uncontrolled state between renders. Leave out `.value(..)` and set `.default_value(..)` for an uncontrolled fader. Use `.on_value_change_with_details(..)` to also get the reason for each change.

## Anatomy

```rust
Fader::new("microphone")
    .value(db)
    .on_value_change(set_db)
    .child(FaderLabel::new("Microphone"))
    .child(FaderReset::new())
    .child(FaderValue::new().editable(true))
    .child(
        FaderTrack::new()
            .child(FaderRange::new())
            .child(FaderThumb::new()),
    )
    .child(FaderScale::new())
```

A fader with no children gets a track, range and thumb. The parts read the fader's state while they render, so they can sit in any layout inside it, such as a `div()` row for the label, reset and value. `FaderTrack` accepts any children, so a `LevelMeter` can sit inside it.

## Keyboard

| Key                                | Action                         |
| ---------------------------------- | ------------------------------ |
| Arrow keys                         | Change by `step` (0.5 dB)      |
| Shift + arrow, Page Up / Page Down | Change by `large_step` (6 dB)  |
| Alt + arrow                        | Change by `fine_step` (0.1 dB) |
| Home / End                         | Minimum (or silence) / maximum |

Holding Alt while dragging uses `fine_step` resolution.

## Theming

The fader paints with the active `audiocn::Theme`: the track with `input`, the range with `primary`, the thumb with `background` and a `ring` shadow. `FaderTrack`, `FaderRange` and `FaderThumb` implement `Styled`, so `.bg(..)` and other style methods restyle them. The React variables and attributes map to builder options:

| React | GPUI |
| --- | --- |
| `--fader-track-size`, `--fader-thumb-size` | Set by `.size(AudioSize)`: a 3, 4 or 6 px track and a 12, 16 or 20 px thumb |
| `data-orientation`, `data-variant`, `data-size` | `.orientation(..)`, `.variant(..)` and `.size(..)` |
| `data-disabled` | `.disabled(true)` |
| `data-dragging`, `data-at-detent`, `data-silent` | No equivalent. Compare the value in your `on_value_change` handler |

## Accessibility

The thumb is exposed to assistive technology as a slider whose value is the formatted text, such as "−6.0 dB" or "Silent". Name it with `.aria_label(..)`. `FaderLabel` is visible text that focuses the thumb when clicked, but it does not name the thumb in GPUI.

### FaderValue

The value is as wide as the longest text the fader's range can show, and right-aligned, so moving the fader never shifts the layout. The editor opens at the same width.

### FaderScale

Takes [`DbScale`](/docs/gpui/components/db-scale) options: `ticks`, `side`, `labels`, `marks`, `format`, and custom ticks through `child` and `children`. The range, taper and orientation come from the fader.
