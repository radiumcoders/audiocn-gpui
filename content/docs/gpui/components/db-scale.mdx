## Installation

```bash
cargo add audiocn
```

## Usage

```rust
use audiocn::DbScale;
```

```rust
DbScale::new().min_db(-60.).max_db(6.)
```

Inside a `LevelMeter` or `Fader`, use `LevelMeterScale` or `FaderScale` instead: they take the range, orientation and taper from their parent so the ticks line up.

## Anatomy

```rust
use audiocn::{DbScale, DbScaleTick};

DbScale::new()
    .child(DbScaleTick::new(0.))
    .child(DbScaleTick::new(-12.))
```

With no children, the scale renders ticks from `.ticks(..)`, or common values inside the range. Labels that would touch a more important one are hidden on every paint, so a narrow scale stays readable and a resize re-thins it.

## Theming

The scale paints with the active `audiocn::Theme`: marks use `Theme::border` and labels `Theme::muted_foreground`. Restyle the labels with `.text_color(..)` and `.text_size(..)` on the scale.

The React data attributes map to builder options:

| React                                  | GPUI                            |
| -------------------------------------- | ------------------------------- |
| `data-orientation`, `data-side`        | `.orientation(..)`, `.side(..)` |
| `data-major`                           | `DbScaleTick::major(..)`        |
| `[&_[data-slot=db-scale-mark]]:hidden` | `.marks(false)`                 |

## Accessibility

The scale is decorative and adds nothing to the accessibility tree: the meter or fader it belongs to already reports its value.
