## Installation

```cargo
cargo add audiocn
```

To play the sounds natively with `audiocn::io::use_sound`, add the `device` feature:

```cargo
cargo add audiocn --features device
```

## Usage

```rust
use audiocn::io::{SoundOptions, use_sound};
use audiocn::{SoundPad, SoundPadLabel, SoundPadProgress, SoundPadShortcut};
```

```rust
let airhorn = use_sound("airhorn", Some("/sounds/airhorn.mp3"), SoundOptions::default(), window, cx);

SoundPad::new("airhorn")
    .hotkey("1")
    .playing(airhorn.is_playing())
    .on_trigger({
        let airhorn = airhorn.clone();
        move |_, _| airhorn.play()
    })
    .child(SoundPadLabel::new().child("Airhorn"))
    .child(SoundPadShortcut::new())
    .child(SoundPadProgress::new().source(airhorn.progress()))
```

The pad plays nothing itself. It reports triggers; [`use_sound`](/docs/gpui/hooks/use-sound) or your own engine does the playback. `SoundPad::new` takes an element id, which keeps the pad's focus and pressed state between renders.

## Anatomy

```rust
SoundPadGrid::new("pads").child(
    SoundPad::new("airhorn")
        .child(SoundPadIcon::new().icon(IconName::Megaphone))
        .child(SoundPadLabel::new())
        .child(SoundPadShortcut::new())
        .child(SoundPadProgress::new()),
)
```

## Modes

| Mode                    | Behaviour                                     |
| ----------------------- | --------------------------------------------- |
| `SoundPadMode::OneShot` | Every press triggers; pressing again restarts |
| `SoundPadMode::Toggle`  | Press to start, press again to stop           |
| `SoundPadMode::Hold`    | Plays while held                              |
| `SoundPadMode::Loop`    | Like toggle, and marks the pad as looping     |

A second press in toggle and loop modes, and the release in hold mode, calls `on_stop`.

## Theming

The pad paints with the active `audiocn::Theme`, tinted with its accent. The React variables and attributes are builder options here:

| React | GPUI |
| --- | --- |
| `--pad-accent` | `SoundPad::accent(Hsla)`, default `theme.primary`. `audiocn::theme::oklch(l, c, h)` builds one |
| `--pad-progress` | `SoundPadProgress::value(f32)` or `::source(FrameSource<f32>)`, 0..1 |
| `--pad-min-width` | `SoundPadGrid::pad_min_width(px)`, the narrowest pad before the grid drops a column. Default 88px |
| `--pad-gap` | `SoundPadGrid::pad_gap(px)`, default 8px |
| `data-playing`, `data-pressed`, `data-mode`, `data-loading` | The `playing`, `mode` and `loading` you pass in; the pad tracks pressed itself |

## Accessibility

A pad is focusable and has the button role. In toggle and loop modes it reports its pressed state. Enter and Space press it, and in hold mode they play until released. The grid moves focus between pads with the arrow keys. A pad's hotkey is its `aria_keyshortcuts`, and `SoundPadShortcut` shows it. Global hotkeys never fire while someone is typing in a field.
