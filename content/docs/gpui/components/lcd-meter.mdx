## Installation

```bash
cargo add audiocn
```

## Usage

```rust
use audiocn::{LcdDisplay, LcdMeter};
```

```rust
LcdDisplay::new("input").child(
    LcdMeter::new("input-level")
        .aria_label("Input level")
        .source(meter.clone()),
)
```

The meter lives on an [LCD Display](/docs/gpui/components/lcd-display)'s screen, so it takes that screen's ink, glass, dot grid and glow, and it can share the screen with settings rows and the status pixel. It panics outside an `LcdDisplay`. It follows your theme the same way: dark pixels on a backlit glass in light mode, glowing ink in dark mode, in the theme's `primary` or a fixed hardware ink.

With no children, it draws one row per channel (labelled L and R for a pair), each with a track, a held peak and a readout, then the scale and a CLIP flag. The metering is [Level Meter](/docs/gpui/components/level-meter)'s: the same sources, ballistics, peak hold and clip hold.

## Anatomy

```rust
use audiocn::{
    LcdDisplay, LcdMeter, LcdMeterBar, LcdMeterChannel, LcdMeterClip, LcdMeterHold, LcdMeterLabel,
    LcdMeterScale, LcdMeterTrack, LcdMeterValue,
};

LcdDisplay::new("input").child(
    LcdMeter::new("input-level")
        .child(
            LcdMeterChannel::new()
                .index(0)
                .child(LcdMeterLabel::new("L"))
                .child(
                    LcdMeterTrack::new()
                        .child(LcdMeterBar::new())
                        .child(LcdMeterHold::new()),
                )
                .child(LcdMeterValue::new()),
        )
        .child(LcdMeterScale::new())
        .child(LcdMeterClip::new()),
)
```

The meter is a three-column grid: labels, tracks and readouts. Each `LcdMeterChannel` is one row of it; the scale sits under the tracks and the CLIP flag under the readouts. GPUI has no CSS grid, so the meter measures its labels and readouts and gives every row the same column widths. The children are typed parts: `LcdMeter::child` takes a channel, the scale or the flag, and `LcdMeterChannel::child` a label, a track or a readout. A readout inside a channel shows that channel; set `.channel(DbReadoutChannel::Max)` to show the loudest.

## Examples

### Inks

The meter has no colours of its own. Set `.variant(..)` on the display for a fixed hardware ink, or `.appearance(LcdDisplayAppearance::Dark)` for a dark screen on a light page.

<GpuiExample demo="lcd-meter" variant="inks" />

### Segments

Segments are whole dots of the display's grid: 3 dots wide with a 1-dot gap by default. A lit segment lights whole, never in part. Set `.segment(..)` to one dot for a fine ladder, or `.gap(px(0.))` for a solid bar.

<GpuiExample demo="lcd-meter" variant="segments" />

```rust
// The display's default pitch is 2px.
LcdMeter::new("fine").segment(px(2.))
LcdMeter::new("solid").gap(px(0.))
```

### Peak and RMS

Layer an `Rms` bar and a `Peak` bar for a dual meter.

```rust
LcdMeterTrack::new()
    .child(LcdMeterBar::new())
    .child(LcdMeterBar::new().measure(LevelMeterMeasure::Rms))
    .child(LcdMeterHold::new())
```

Both bars light in the full ink. `LcdMeterBar` has no opacity option yet, so the React dimmed peak bar (`opacity-40`) has no equivalent.

### Microphone

Custom rows take labels of any length. The meter moves its tracks onto the screen's dot grid, so segments never cut a dot in half. With the `device` feature, `audiocn::io::use_microphone` gives you the meter source.

## Feeding data

A meter accepts levels three ways, as [Level Meter](/docs/gpui/components/level-meter) does. See [Feeding data](/docs/gpui/concepts/feeding-data).

```rust
use audiocn::{ChannelLevel, LcdMeter, LevelMeterActions, MeterFrame};

// A source: the meter reads it while painting and asks for frames only while it moves.
LcdMeter::new("a").source(meter.clone())

// Values: for slow data. Ballistics smooth the movement.
LcdMeter::new("b").peak_db(-9.1).rms_db(-18.)

// A handle: for callers that own their own frame loop.
let actions = LevelMeterActions::new();
LcdMeter::new("c").actions(actions.clone())
// later
actions.paint(MeterFrame::mono(ChannelLevel::new(-9.1)), cx);
```

The meter uses the `TaperInput::Audio` taper by default, which gives the loud end of the range most of the track, like a recorder's screen. Pass `.taper(TaperInput::Linear)` for equal distance per dB.

## Theming

The React CSS variables are builder options on `LcdMeter`:

| React | GPUI | Default |
| --- | --- | --- |
| `--lcd-meter-segment` | `.segment(Pixels)` | 3 dots of the display's pitch |
| `--lcd-meter-gap` | `.gap(Pixels)` | 1 dot. `px(0.)` gives a solid bar |
| `--lcd-meter-thickness` | `.thickness(Pixels)` | 5, 7 or 10 dots for the display's `Sm`, `Default` and `Lg` |
| `--lcd-meter-unlit` | `.unlit(color)` | Unlit segments and the CLIP flag at rest: the lit pixels at 14% |
| `--lcd-display-*` | Options on `LcdDisplay` | Everything else: the ink, lit and dim pixels, glass, glow, pitch and font. See [LCD Display](/docs/gpui/components/lcd-display#theming) |

The parts are fixed types, so the React data attributes (`data-zone`, `data-clipping`, `data-active`, `data-size`, `data-measure`) have nothing to style. Read clipping with `LcdMeterClip::on_clipping_change(..)` or `LevelMeterActions::clipping(cx)`.

The screen has one ink, so zones show as a bracket printed over the clip zone and a CLIP flag that inverts while the signal clips.

## Accessibility

- The meter has the AccessKit role `Meter` with its value in dB, updated at most four times a second. Give it a name with `.aria_label(..)`.
- The CLIP flag is a focusable button that turns the flag off on click, Enter or Space. Its label changes to "Clipping. Reset clip indicator" while it is on.
- With reduced motion, set with `audiocn::signal::reduced_motion::set_reduced_motion(true, cx)`, the meter shows the current level four times a second instead of animating.
