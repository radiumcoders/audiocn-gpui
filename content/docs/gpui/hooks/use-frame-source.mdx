Every audiocn meter and visualizer reads its `.source(..)` this way. Use it to build your own components on any frame source.

```bash
cargo add audiocn
```

## Usage

React subscribes a callback to a source. In GPUI a `FrameSource` is a shared slot that holds the latest frame, so there is nothing to subscribe to: read it while you render or paint, and ask for another frame while it moves.

```rust
use audiocn::audio::decibels::{DEFAULT_MAX_DB, DEFAULT_MIN_DB, db_to_level};
use audiocn::{ActiveTheme, FrameSource, MeterFrame};
use gpui::{App, IntoElement, RenderOnce, Window, div, prelude::*, px, relative};

#[derive(IntoElement)]
pub struct TinyMeter {
    source: FrameSource<MeterFrame>,
}

impl RenderOnce for TinyMeter {
    fn render(self, window: &mut Window, cx: &mut App) -> impl IntoElement {
        let peak_db = self.source.with_latest(|frame| {
            frame.and_then(|frame| frame.channels.first()).map_or(f32::NEG_INFINITY, |c| c.peak_db)
        });
        let level = db_to_level(peak_db, DEFAULT_MIN_DB, DEFAULT_MAX_DB);
        // Render again next frame to pick up the next level.
        window.request_animation_frame();

        div()
            .h(px(8.))
            .w(px(160.))
            .rounded_full()
            .bg(cx.theme().muted)
            .child(div().h_full().w(relative(level)).rounded_full().bg(cx.theme().primary))
    }
}
```

`with_latest` reads the frame in place without cloning it. It asks for a frame every time it renders, which is fine for one small meter.

audiocn's meters go further and sleep once they settle. A frame from another thread can't wake a sleeping element, because GPUI only renders when asked, so the meters check `version()` on a short timer while they sleep, and request animation frames again when it changes. `FrameTask` in `audiocn::audio::frame_loop` gives you the same awake and asleep state machine for your own painters.
