seoDescription: use_mixer keeps mixer state in GPUI, with gain, mute, solo, pan and monitor per channel plus a master, and knows which channels are audible. No audio attached.
---

```bash
cargo add audiocn
```

## Usage

```rust
use audiocn::signal::mixer::{MixerChannelInit, MixerOptions, use_mixer};

let mixer = use_mixer(
    "mixer",
    MixerOptions {
        channels: vec![MixerChannelInit::new("mic"), MixerChannelInit::new("music").gain_db(-12.)],
        ..Default::default()
    },
    window,
    cx,
);

mixer.update(cx, |mixer, cx| {
    mixer.set_gain("mic", -3.);
    mixer.set_solo("music", true, true);
    mixer.is_audible("mic"); // false while music is soloed
    cx.notify();
});
```

`use_mixer` returns an `Entity<MixerStore>` kept under its id. The options only seed it on the first render; change it from callbacks and call `cx.notify()` to re-render. A `MixerStore` dereferences to the `MixerState`, so every method below works on it.

`use_mixer` only holds state. Connect it to sound with [`WebAudioMixer`](/docs/gpui/hooks/use-web-audio-mixer), or read `mixer.state` and send it to your own engine.

## Options

`MixerOptions`:

<PropsTable
  rows={[
    [
      "channels",
      "Vec<MixerChannelInit>",
      "[]",
      "Initial channels: MixerChannelInit::new(id) with gain_db, muted, solo, pan and monitor builders. Missing fields get defaults.",
    ],
    ["master", "MixerMasterPatch", "{ gain_db: 0., muted: false }", null],
  ]}
/>

A channel is `MixerChannelState { id, gain_db, muted, solo, pan, monitor }`. `pan` runs from −1 to 1. React's controlled `state`, `onStateChange` and `persistKey` have no options here: the store is yours to read after each change and to save yourself.
